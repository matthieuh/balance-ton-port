# Balance ton port

macOS menu bar app plus the `btp` CLI, both on one Rust core, plus a Claude Code plugin. It kills dev servers that coding-agent sessions left behind, so a bug here can kill the wrong process. Read the README's "Safety rules" before changing anything in the kill path.

## Layout

- `crates/btp-core`: everything that decides and acts. `decide.rs` (pure rules, no clock, no I/O), `watcher.rs` (scan, track, kill), `watcher/session.rs` (session-end sweep, `kill_own`), `platform/` (libproc, signals), `agents/` (Claude Code and Codex session detection), `restart.rs`, `observed.rs` (servers no agent started).
- `crates/btp-cli`: the `btp` binary (`main.rs`, `run.rs` for `btp run`).
- `crates/btp-ffi`: UniFFI bridge to the app.
- `app/`: SwiftUI menu bar app (Swift 6, strict concurrency), project generated by xcodegen from `app/project.yml`.
- `plugin/`: Claude Code plugin (hooks in shell, skill, commands).
- `scripts/`: build, release and test scripts.

## Commands

```bash
cargo fmt --all -- --check
cargo clippy --locked --all-targets -- -D warnings
cargo test --locked                    # also builds target/debug/btp for the Swift tests
scripts/test-plugin.sh                 # plugin hooks, needs shellcheck
bash scripts/test-release-scripts.sh
scripts/build-xcframework.sh && (cd app && xcodegen generate) && \
  xcodebuild -project app/BalanceTonPort.xcodeproj -scheme BalanceTonPort -destination 'platform=macOS' test
```

Tests isolate themselves with `BTP_DATA_DIR` in a temp dir. Never point them at a real `~/.claude` (`CLAUDE_CONFIG_DIR` must stay unset).

## Safety invariants

A change that breaks one of these is a security bug (see SECURITY.md), not a regular bug. Every change to the files named here needs a test that would fail if the invariant broke.

1. **Only agent-started servers are stopped automatically.** A server no live coding-agent session started (an "observed" server) is never stopped by a rule, `btp kill`, `btp sweep` or the skill. Only the app's manual Stop/Restart reaches it, one at a time, after a confirmation. See `Watcher::kill` vs `Watcher::stop_observed` in `watcher.rs`.
2. **A worktree used by another live session is never touched.** `Observation::shared_with_live_session` short-circuits `decide` (`decide.rs`), and no other path may bypass it.
3. **Agent CLIs are never tracked or signalled**, nor anything they run, even when found inside a server's tree. See `agents::is_agent_cli` and `own_descendants` in `watcher.rs`.
4. **Excluded commands and ports are re-checked on every scan and right before each kill.** An excluded child (a database the dev server started) is never signalled when its parent is killed. See `is_excluded` and `term_tree`.
5. **No signal without a start-time check.** Every target is snapshotted as `(pid, start_time)` and re-checked right before each SIGTERM and SIGKILL, so a reused pid is never hit. All signals go through `signal_checked` (which also refuses pid <= 1 and ourselves). Any new call to `Platform::signal` that bypasses it is a bug.
6. **The process environment never reaches disk, a log or an error message.** `restart.rs` reads it from the live process at restart time and hands it straight to the child. Its `Debug` impl prints only the entry count.
7. **`btp sweep --dry-run` sends nothing.**

Kill timing is part of the contract too: worktree deleted means kill at once; session dead and port idle for `dead_session_idle_s` means kill; session alive and idle for `alert_after_s` means alert, never kill. Postpone and Keep only change the second and third rules.

## Conventions

- Conventional commits (`feat:`, `fix(app):`, `chore:`, `docs:`), squash-merged PRs.
- User-facing copy exists in English and French. Follow LOCALIZATION.md, and update `app/Sources/Localizable.xcstrings` along with any new string.
- README describes behavior precisely. A change to a rule, a default or a safety guarantee updates the README in the same PR.
- Third-party GitHub Actions are pinned to a commit SHA with the version in a comment.
- Keep PRs small enough to review. Separate safety-core changes (`btp-core` kill path, `decide.rs`, `platform/`) from UI and copy changes.

## Reviewing

When reviewing a change, look for bugs and invariant breaks, not style: rustfmt and clippy `-D warnings` already run in CI. In order:

1. Does it break a safety invariant above, or open a new path to `Platform::signal`, `kill_tree`, `term_tree`, `stop_observed_tree` or `restart`?
2. Races: a scan result used after the state it describes may have changed (pid reuse, a session that just ended, a port taken by another process since).
3. Is the behavior change covered by a test, and does README or the French copy need an update?
4. Swift: main-actor and `Sendable` correctness, and FFI calls that can block the UI thread.
5. Shell (plugin hooks): quoting, `set -euo pipefail` handling, and anything that could fail a user's Claude Code session instead of failing quietly.
